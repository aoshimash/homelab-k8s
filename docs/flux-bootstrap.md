# Flux Bootstrap Guide

This document describes how to bootstrap Flux CD for GitOps management of the homelab Kubernetes cluster.

## Prerequisites

### Required Tools

Install the Flux CLI:

```bash
brew install fluxcd/tap/flux
```

Verify the installation:

```bash
flux --version
```

### Cluster Requirements

- A running Kubernetes cluster (see [Talos Bootstrap Guide](./talos-bootstrap.md))
- `kubectl` configured to access the cluster
- Cluster admin permissions

Verify cluster access:

```bash
kubectl cluster-info
flux check --pre
```

## GitHub Authentication

### Create a Fine-grained Personal Access Token (PAT)

For security, we use a fine-grained PAT which allows repository-specific permissions.

1. Go to GitHub: **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens**

2. Click **Generate new token**

3. Configure the token:

   | Setting | Value |
   |---------|-------|
   | Token name | `flux-homelab-k8s` |
   | Expiration | No expiration (or your preference) |
   | Resource owner | Your account (`aoshimash`) |
   | Repository access | **Only select repositories** → `homelab-k8s`, `homelab-k8s-private` |

4. Set **Repository permissions**:

   | Permission | Access Level |
   |------------|--------------|
   | Administration | Read-only |
   | Contents | Read and write |
   | Metadata | Read-only |

   > **Note**: If you want to use SSH deploy keys instead of token auth, set `Administration` to `Read and write`.

   These permissions are what `flux bootstrap` needs: it pushes the Flux
   manifests to the repository. The controllers only ever read, so once
   bootstrap is done, replace the stored token with a read-only one (see
   [Rotating the Flux token](#rotating-the-flux-token)).

5. Click **Generate token** and copy the token

6. Export the token as an environment variable:

   ```bash
   export GITHUB_TOKEN=<your-fine-grained-pat>
   ```

### Rotating the Flux token

Flux reads both `homelab-k8s` and `homelab-k8s-private` with the token in the
`flux-system` Secret (`username: git`, `password: <PAT>`). When that token stops
working, both GitRepositories turn not ready with
`authentication required: Invalid username or token`. Flux then **keeps
applying the last revision it fetched**, so merged changes stop reaching the
cluster without any other visible failure. This happened from 2026-10-19 to
2026-10-20, when the PAT was deleted: nothing merged after `f3eed02` was
applied until the token was replaced.

1. Create a fine-grained PAT:

   | Setting | Value |
   |---------|-------|
   | Repository access | **Only select repositories** → `homelab-k8s`, `homelab-k8s-private` |
   | Repository permissions | `Contents`: Read-only, `Metadata`: Read-only |
   | Expiration | Your preference. Personal accounts may choose no expiration |

2. Put it into the Secret from an interactive terminal (`read` waits for the
   token to be pasted, and does not echo it or record it in shell history):

   ```bash
   read -rs GITHUB_TOKEN && kubectl -n flux-system create secret generic flux-system --from-literal=username=git --from-literal=password="$GITHUB_TOKEN" --dry-run=client -o yaml | kubectl apply --server-side --force-conflicts -f - ; unset GITHUB_TOKEN
   ```

   Use `--server-side`. Client-side `kubectl apply` (and `kubectl replace` on
   an object that already has one) also writes the whole Secret, token
   included, into the `kubectl.kubernetes.io/last-applied-configuration`
   annotation, where any `-o yaml`/`-o json` dump of the Secret's metadata
   prints it. If that annotation is present, remove it:

   ```bash
   kubectl -n flux-system annotate secret flux-system kubectl.kubernetes.io/last-applied-configuration-
   ```

3. Confirm both sources fetch again:

   ```bash
   flux reconcile source git flux-system
   flux reconcile source git homelab-k8s-private
   ```

## Project Structure

After bootstrap, the repository will have the following structure:

```
homelab-k8s/
├── docs/
│   ├── talos-bootstrap.md
│   └── flux-bootstrap.md
├── infra/
│   └── talos/                     # Talos configuration (outside Flux)
├── k8s/                           # Flux-managed Kubernetes resources
│   ├── flux/                      # Flux system (auto-generated by bootstrap)
│   │   └── flux-system/
│   │       ├── gotk-components.yaml
│   │       ├── gotk-sync.yaml
│   │       └── kustomization.yaml
│   ├── infrastructure/            # Cluster infrastructure (ingress, cert-manager, etc.)
│   │   └── kustomization.yaml
│   └── apps/                      # User applications
│       └── kustomization.yaml
├── age.agekey
├── LICENSE
└── README.md
```

### Directory Responsibilities

| Directory | Description |
|-----------|-------------|
| `infra/talos/` | Talos Linux configuration (applied outside cluster) |
| `k8s/flux/` | Flux system components (auto-managed) |
| `k8s/infrastructure/` | Cluster infrastructure: CNI, ingress, cert-manager, monitoring |
| `k8s/apps/` | User applications deployed on the cluster |

## Bootstrap Flux

### 1. Run Bootstrap Command

```bash
flux bootstrap github \
  --token-auth \
  --owner=aoshimash \
  --repository=homelab-k8s \
  --branch=main \
  --path=k8s/flux \
  --personal
```

**Parameters explained:**

| Parameter | Value | Description |
|-----------|-------|-------------|
| `--token-auth` | - | Use GitHub PAT for authentication (HTTPS) |
| `--owner` | `aoshimash` | GitHub username or organization |
| `--repository` | `homelab-k8s` | Repository name |
| `--branch` | `main` | Git branch to use |
| `--path` | `k8s/flux` | Path in repository for Flux manifests |
| `--personal` | - | Repository is owned by a personal account |

### 2. Verify Installation

Check that Flux components are running:

```bash
# Check Flux pods
kubectl -n flux-system get pods

# Check Flux components status
flux check

# View GitRepository status
flux get sources git

# View Kustomization status
flux get kustomizations
```

Expected output:
- All pods in `flux-system` namespace are `Running`
- GitRepository shows `Ready` with latest commit
- Kustomization shows `Ready` and `Applied`

## Post-Bootstrap Setup

### 1. Create Infrastructure Kustomization

Create the directory structure for infrastructure components:

```bash
mkdir -p k8s/infrastructure/controllers
mkdir -p k8s/infrastructure/configs
```

Create `k8s/infrastructure/kustomization.yaml`:

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources: []
  # - controllers/ingress-nginx
  # - controllers/cert-manager
  # - configs/cluster-issuers
```

Create the Flux Kustomization to deploy infrastructure:

```yaml
# k8s/flux/infrastructure-kustomization.yaml
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: infrastructure
  namespace: flux-system
spec:
  interval: 10m
  sourceRef:
    kind: GitRepository
    name: flux-system
  path: ./k8s/infrastructure
  prune: true
  wait: true
  # If you use SOPS-encrypted secrets (*.sops.yaml), enable decryption and
  # provide the age private key via the `sops-age` Secret in `flux-system`.
  decryption:
    provider: sops
    secretRef:
      name: sops-age
```

### 2. Create Apps Kustomization

Create the directory structure for applications:

```bash
mkdir -p k8s/apps
```

Create `k8s/apps/kustomization.yaml`:

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources: []
  # - my-app
```

Create the Flux Kustomization to deploy apps (depends on infrastructure):

```yaml
# k8s/flux/apps.yaml
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: apps
  namespace: flux-system
spec:
  interval: 10m
  sourceRef:
    kind: GitRepository
    name: flux-system
  path: ./k8s/apps
  prune: true
  wait: true
  dependsOn:
    - name: infrastructure
```

### 3. Commit and Push

```bash
git add k8s/
git commit -m "feat: add infrastructure and apps kustomizations"
git push
```

### 4. Verify Reconciliation

```bash
# Force reconciliation
flux reconcile source git flux-system

# Check all kustomizations
flux get kustomizations

# Watch for changes
flux get kustomizations --watch
```

## SOPS Integration (Required if you use `*.sops.yaml`)

To manage secrets with SOPS and Age encryption:

### 1. Create the age private key Secret (out-of-band)

This Secret contains the **age private key** used by Flux to decrypt SOPS files during reconciliation.
It **must not** be committed to Git.

Create or update it in an idempotent way:

```bash
kubectl -n flux-system create secret generic sops-age \
  --from-file=age.agekey=./age.agekey \
  --dry-run=client -o yaml | kubectl apply -f -
```

### 2. Configure Flux Kustomization for SOPS

Add decryption configuration to your Kustomizations:

```yaml
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: infrastructure
  namespace: flux-system
spec:
  # ... other fields ...
  decryption:
    provider: sops
    secretRef:
      name: sops-age
```

### 3. Verify decryption is wired

```bash
kubectl -n flux-system get secret sops-age
kubectl -n flux-system get kustomization infrastructure -o yaml | sed -n '1,120p'
```

### Restore age key from Bitwarden

If you are rebuilding the cluster or setting up a new machine, restore `age.agekey` from the Bitwarden vault before running the steps above.

1. Open Bitwarden and locate the item named **`homelab-k8s`**. Find the age private key field and copy its value.

2. Write the value to `age.agekey` at the project root:

   ```bash
   # Paste the copied value into the file (replace the content below with the actual key)
   cat > age.agekey <<'EOF'
   # created: ...
   # public key: age1...
   AGE-SECRET-KEY-1...
   EOF
   ```

3. Recreate the `sops-age` Secret in the cluster:

   ```bash
   kubectl -n flux-system create secret generic sops-age \
     --from-file=age.agekey=./age.agekey \
     --dry-run=client -o yaml | kubectl apply -f -
   ```

## Multi-Source Reconciliation (Private Repository)

Flux can reconcile manifests from multiple Git repositories. The `homelab-k8s-private` repository contains components with private configuration (e.g., radigo-recorder) that are deployed into the same cluster.

### How It Works

Two additional resources in `k8s/flux/` enable this:

- **`private-gitrepository.yaml`** — A `GitRepository` source pointing to `homelab-k8s-private`, using the same `flux-system` secret for authentication
- **`private-apps-kustomization.yaml`** — A `Kustomization` that deploys from the private repository with `dependsOn: apps` to ensure correct ordering and SOPS decryption enabled

### PAT Requirements

The fine-grained PAT used by Flux (`flux-system` secret) must have access to **both** repositories:

- `homelab-k8s` (public — main infrastructure)
- `homelab-k8s-private` (private — personal configuration)

If the PAT was originally created with access only to `homelab-k8s`, update it:

1. Go to GitHub: **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens**
2. Edit the `flux-homelab-k8s` token
3. Under **Repository access**, add `homelab-k8s-private` to the selected repositories
4. Save the token

If the token value changes, update the `flux-system` secret in the cluster as
described in [Rotating the Flux token](#rotating-the-flux-token). Re-running
`flux bootstrap` is not needed for a token change.

### Verify Private Repository Reconciliation

```bash
# Check GitRepository source
flux get sources git homelab-k8s-private

# Check Kustomization status
flux get kustomization private-apps

# Describe for detailed error if not Ready
kubectl -n flux-system describe gitrepository homelab-k8s-private
```

## Useful Commands

### Reconciliation

```bash
# Reconcile GitRepository
flux reconcile source git flux-system

# Reconcile all Kustomizations
flux reconcile kustomization flux-system
flux reconcile kustomization infrastructure
flux reconcile kustomization apps
flux reconcile kustomization private-apps
```

### Debugging

```bash
# View Flux logs
flux logs

# View specific controller logs
flux logs --kind=Kustomization --name=flux-system

# Check events
kubectl -n flux-system get events --sort-by='.lastTimestamp'
```

### Suspend/Resume

```bash
# Suspend reconciliation (for maintenance)
flux suspend kustomization flux-system

# Resume reconciliation
flux resume kustomization flux-system
```

## Troubleshooting

### GitRepository Not Ready

```bash
# Check GitRepository status
flux get sources git -A

# Describe for detailed error
kubectl -n flux-system describe gitrepository flux-system
```

Common causes:
- Invalid GitHub token (`authentication required: Invalid username or token`) —
  see [Rotating the Flux token](#rotating-the-flux-token)
- Repository not accessible
- Branch doesn't exist

### Kustomization Failed

```bash
# Check Kustomization status
flux get kustomizations -A

# View detailed error
kubectl -n flux-system describe kustomization <name>

# Check logs
flux logs --kind=Kustomization --name=<name>
```

Common causes:
- Invalid YAML syntax
- Missing resources referenced in kustomization.yaml
- RBAC permissions

### Force Sync

```bash
# Delete and recreate the source
flux reconcile source git flux-system --force
```

## Uninstall Flux

To completely remove Flux from the cluster:

```bash
flux uninstall --silent
```

> **Warning**: This will remove all Flux components and CRDs. Resources deployed by Flux will remain but won't be managed anymore.
